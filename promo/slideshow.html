WHAT IT IS

Every session gets a name.

dsh-cowork-amber · idle dsh-memory-azure · running dsh-polyglot-coral · idle
See everyoneAny live session on the machine, one list.list_agents peers
Message by nameAddress a session, not a process id.send_message to="dsh-memory-azure"
No daemonHeartbeat files + atomic writes. That's the whole registry.~/.dsh/crosstalk/

THE PROBLEM

Your sessions are islands.

Today

A session can only talk to its own subagents.
Two sessions in two repos?

You copy-paste between terminals.

With dsh-crosstalk

Any session ↔ any session.
list them, message them, reply by name.

One repo, one session — they coordinate.

SEE IT

A message. Across sessions.

dsh-cowork-amber — ~/work/dsh-cowork
$ list_agents peers
  dsh-cowork-amber [idle]  — ~/work/dsh-cowork
  dsh-memory-azure  [idle] — ~/work/dsh-memory
$ send_message to="dsh-memory-azure"
    message="round-trip check — copy?"
✓ message queued for dsh-memory-azure
← "loud and clear. ping me at standup."
dsh-memory-azure — ~/work/dsh-memory
… idle — watching ~/.dsh/crosstalk/inbox/
message from session dsh-cowork-amber (~/work/dsh-cowork)
round-trip check — copy?
Reply: send_message to="dsh-cowork-amber" …

THE WHOLE API

Two commands.

$ list_agents peers
Who's alive, what they're doing, where they live — name · status · cwd · last activity.
$ send_message to="dsh-memory-azure" message="…"
Delivered as a labeled turn. Idle session? It wakes up. Busy? Next turn boundary.

Replying is just send_message back — the sender's name rides along on every message.

TRUST, BY CONSTRUCTION

Peer requests.
Not user orders.

Same-user onlyNo network, no daemon, no daemon ports. OS-uid checked both ways.accept: same-user
AuditableEvery turn is labeled and written to the append-only log with its provenance.source: crosstalk
Allowlist modeLock inbound to named sessions or cwd globs.mode: allowlist

INSTALL

Straight from GitHub — no npm step. Add it to every profile that should join the conversation.
